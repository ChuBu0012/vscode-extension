1. สถาปัตยกรรม & Process Model ของ VS Code

VS Code ถูกออกแบบบนสถาปัตยกรรมแยก Process (Multi-Process Architecture) ซึ่งเป็นหัวใจสำคัญที่ทำให้ตัวโปรแกรมทำงานได้ลื่นไหล ไม่ค้าง แม้ว่าผู้ใช้จะเปิด Extension ไว้หลายสิบตัว

🎨 VS Code UI (Renderer Process)

ทำงานด้วย Electron/Chromium จัดการ Editor Tab, Sidebar, StatusBar, Syntax Highlighting ขั้นต้น และ Webview DOM ทำงานที่ 60 FPS เสมอ Extension จะไม่มีสิทธิ์เข้าถึง DOM ส่วนนี้โดยตรง

⚙️ Extension Host (Node.js Process)

เป็น Process แยกต่างหากสำหรับรันโค้ด Extension ทั้งหมด สื่อสารกับ UI ผ่าน IPC (JSON-RPC) มี Node.js API เต็มรูปแบบ (fs, path, net, worker_threads) และติดต่อกับ VS Code ผ่าน Namespace vscode.*

⚠️ กฎเหล็ก: Single-Threaded Isolation & สิ่งที่ห้ามทำ

Extension ทั้งหมดในเครื่องจะทำงานบน Thread เดียวกันใน Extension Host หาก Extension ของคุณทำการประมวลผลที่กิน CPU หนักๆ แบบ Synchronous (เช่น fs.readFileSync ก้อนใหญ่, loop หนัก, หรือ regex ที่ติด backtracking) Extension ตัวอื่นทั้งหมดของผู้ใช้จะค้างไปด้วย และ VS Code จะขึ้นเตือนผู้ใช้ว่า "Extension host is unresponsive"
วิธีแก้: งานประมวลผลหนัก ให้ใช้ Asynchronous (async/await), Streams, หรือส่งให้ Node.js Worker Threads

วงจรชีวิตของ Extension (Lifecycle)

ไฟล์ทางเข้า (Entry Point เช่น src/extension.ts) จะมีฟังก์ชันบังคับ 2 ตัว:

src/extension.ts
import * as vscode from 'vscode';

// เรียกเมื่อ Extension ถูก Activate ตามเงื่อนไขใน Activation Events
export function activate(context: vscode.ExtensionContext) {
  console.log('Extension is activated!');

  // ลงทะเบียนคำสั่งและเก็บ Disposable เสมอ
  const disposable = vscode.commands.registerCommand('myExt.doSomething', () => {
    vscode.window.showInformationMessage('Hello from Extension!');
  });

  context.subscriptions.push(disposable);
}

// เรียกเมื่อปิด VS Code หรือสั่ง Disable Extension
export function deactivate() {
  // Disposables ใน context.subscriptions จะถูกคืนหน่วยความจำอัตโนมัติ
  // หากมี socket, process นอกระบบ ให้สั่งปิดที่นี่
}

กฎเหล็กการจัดการ Memory: The Disposable Pattern

ใน VS Code ทุกอย่างที่สร้างหรือลงทะเบียนขึ้นมา (Commands, Status Bar Items, Event Listeners, Providers) จะคืนค่าออบเจกต์ที่มีเมธอด dispose(): any

  • ต้องทำ: ดันเข้า context.subscriptions.push(...) เสมอ
  • ผลลัพธ์ถ้าลืม: เมื่อ Extension ถูก Reload หรือ Deactivate Event Listener จะยังคงค้างอยู่ในระบบ ก่อให้เกิด Memory Leak

2. ผ่าโครงสร้าง Manifest (package.json) & Contributions

ไฟล์ package.json คือพิมพ์เขียว (Manifest) ที่ VS Code ใช้อ่านข้อมูลก่อนที่จะโหลดโค้ดจริง

Field ใน package.json ความหมายและข้อกำหนด
name / publisher รหัส Extension (ตัวพิมพ์เล็ก-ขีดกลาง) และ ID ผู้เผยแพร่ (เช่น most-too)
engines.vscode เวอร์ชันขั้นต่ำของ VS Code ที่รองรับ (เช่น ^1.90.0) ห้ามใส่ *
main จุดเริ่มต้นของไฟล์ bundle เช่น ./dist/extension.js
activationEvents ใน VS Code สมัยใหม่ แนะนำให้ปล่อยเป็น [] ว่างๆ เพื่อใช้ Implicit Activation
contributes จุดเชื่อมต่อระบบ (Contribution Points) เช่น คำสั่ง, เมนู, คีย์ลัด, แผงควบคุม

Contribution Points ที่พบบ่อยที่สุด

package.json (ส่วน contributes)
{
  "contributes": {
    "commands": [
      {
        "command": "myExt.formatSnippet",
        "title": "Format Current Snippet",
        "category": "My Tool"
      }
    ],
    "keybindings": [
      {
        "command": "myExt.formatSnippet",
        "key": "ctrl+shift+k",
        "mac": "cmd+shift+k",
        "when": "editorTextFocus"
      }
    ],
    "menus": {
      "editor/context": [
        {
          "command": "myExt.formatSnippet",
          "group": "modification@1",
          "when": "editorHasSelection"
        }
      ]
    }
  }
}
💡 การใช้ "when" Clauses ควบคุมการแสดงผลตาม Context

ใช้ when เพื่อเปิด/ปิดการทำงานหรือการมองเห็นปุ่มคำสั่ง เช่น:

  • editorTextFocus: กำลังพิมพ์อยู่ใน Text Editor
  • editorHasSelection: ผู้ใช้กำลังคลุมแถบข้อความ
  • resourceLangId == typescript: ทำงานเฉพาะเมื่อเปิดไฟล์ TypeScript
  • config.myExt.enabled: ทำงานตามค่า Config ที่ผู้ใช้ตั้งไว้

3. UI Surfaces & รูปแบบการโต้ตอบกับผู้ใช้ (User Interaction)

VS Code มีพื้นที่สำหรับติดต่อกับผู้ใช้อย่างเป็นระบบ โดยแต่ละส่วนมีจุดประสงค์เฉพาะตัว:

3.1 Status Bar Item (แถบแสดงสถานะด้านล่าง)

เหมาะสำหรับแสดงสถานะที่ผู้ใช้ชำเลืองมองได้ตลอดเวลา เช่น จำนวนคำ, โหมดการทำงาน, หรือไอคอนคลิกเพื่อสั่งการ

StatusBar API
const statusItem = vscode.window.createStatusBarItem(
  vscode.StatusBarAlignment.Right, // ชิดขวา
  100                             // Priority (ยิ่งสูง ยิ่งชิดซ้ายของฝั่งขวา)
);

statusItem.command = 'myExt.openDashboard';
statusItem.text = '$(pulse) Syncing...'; // รองรับ Codicons เช่น $(zap), $(gear)
statusItem.tooltip = 'คลิกเพื่อดูสถานะการซิงก์';
statusItem.show();

context.subscriptions.push(statusItem);

3.2 QuickPick & InputBox (กล่องเลือกตัวเลือกและรับข้อความ)

เป็นวิธีที่สะดวกและเป็นธรรมชาติที่สุดใน VS Code ในการถามคำถามหรือให้ผู้ใช้เลือกข้อมูล

QuickPick & InputBox API
// 1. รับข้อความจากผู้ใช้
const projectName = await vscode.window.showInputBox({
  title: 'สร้างโปรเจกต์ใหม่',
  prompt: 'กรุณากรอกชื่อโปรเจกต์ (ภาษาอังกฤษตัวพิมพ์เล็ก)',
  placeHolder: 'my-awesome-tool',
  validateInput: (value) => {
    return /^[a-z0-9-]+$/.test(value) ? null : 'ชื่อต้องประกอบด้วย a-z, 0-9 และ - เท่านั้น';
  }
});

// 2. ให้เลือกจากรายการ QuickPick
const selectedOption = await vscode.window.showQuickPick(
  [
    { label: 'TypeScript', description: 'สร้างเป็นโปรเจกต์ TS', picked: true },
    { label: 'JavaScript', description: 'สร้างเป็นโปรเจกต์ JS ธรรมดา' }
  ],
  { title: 'เลือกภาษาเป้าหมาย', placeHolder: 'ค้นหาภาษา...' }
);

3.3 Notifications vs Progress Bar (การแจ้งเตือน)

กฎ UX: อย่าสแปม Information Popups

ห้ามใช้ vscode.window.showInformationMessage พร่ำเพรื่อเมื่อเปิดโปรแกรม ให้ใช้ต่อเมื่อผู้ใช้กดปุ่มสั่งทำอะไรบางอย่างเท่านั้น หากเป็นงานที่ใช้เวลานาน ให้ใช้ Progress Bar เสมอ

Progress Bar API
await vscode.window.withProgress(
  {
    location: vscode.ProgressLocation.Notification, // แสดงกล่อง progress มุมขวาล่าง
    title: 'กำลังดาวน์โหลดข้อมูล...',
    cancellable: true
  },
  async (progress, token) => {
    token.onCancellationRequested(() => {
      console.log('ผู้ใช้กดยกเลิก');
    });

    progress.report({ increment: 20, message: 'ขั้นตอนที่ 1/3' });
    await sleep(1000);

    progress.report({ increment: 50, message: 'ขั้นตอนที่ 2/3' });
    await sleep(1000);

    progress.report({ increment: 30, message: 'เสร็จสิ้น!' });
  }
);

3.4 TreeView (เมนูต้นไม้ใน Sidebar)

สร้างโครงสร้างโฟลเดอร์/รายการใน Sidebar โดยใช้ TreeDataProvider<T>

TreeDataProvider Implementation
export class SimpleTreeProvider implements vscode.TreeDataProvider {
  getTreeItem(element: string): vscode.TreeItem {
    const item = new vscode.TreeItem(element, vscode.TreeItemCollapsibleState.None);
    item.iconPath = new vscode.ThemeIcon('file');
    return item;
  }

  getChildren(element?: string): string[] {
    if (!element) {
      return ['รายการที่ 1: เครื่องมือหลัก', 'รายการที่ 2: บันทึกส่วนตัว', 'รายการที่ 3: สรุปงาน'];
    }
    return [];
  }
}

// ใน activate():
vscode.window.registerTreeDataProvider('mySidebarView', new SimpleTreeProvider());

4. การทำงานกับ Text Editor และ Documents

การอ่านข้อความ, แก้ไขโค้ด, และการตรวจจับเหตุการณ์ใน Editor:

การอ่านและแก้ไขเนื้อหาใน Editor
const editor = vscode.window.activeTextEditor;
if (!editor) {
  vscode.window.showWarningMessage('ไม่มีไฟล์ที่เปิดใช้งานอยู่');
  return;
}

const document = editor.document;
const selection = editor.selection;

// 1. อ่านข้อความที่ผู้ใช้กำลังคลุมไว้ (Selection)
const selectedText = document.getText(selection);

// 2. สั่งแก้ไขข้อความอย่างปลอดภัย (atomic edit)
await editor.edit((editBuilder) => {
  if (selection.isEmpty) {
    // ถ้าไม่ได้คลุมข้อความ ให้แทรกที่ตำแหน่ง Cursor ปัจจุบัน
    editBuilder.insert(selection.active, '// Auto-generated comment\n');
  } else {
    // แปลงข้อความที่คลุมเป็นตัวพิมพ์ใหญ่
    editBuilder.replace(selection, selectedText.toUpperCase());
  }
});

5. Webviews & Custom UI (สร้างหน้าต่างด้วย HTML/CSS/JS)

เมื่อ UI สำเร็จรูปของ VS Code ไม่เพียงพอ คุณสามารถใช้ Webview เพื่อเรนเดอร์หน้าเว็บอิสระ (HTML/CSS/React/Vue) ใน Editor Tab หรือ Sidebar ได้

🛡️ ความปลอดภัยของ Webview และ CSP (Content Security Policy)

Webview มีสภาพแวดล้อมเหมือน Browser แยกต่างหาก แต่เพื่อความปลอดภัยสูงสุด:

  1. ต้องมี CSP Meta Tag เสมอ ไม่อนุญาตให้โหลด script สุ่มเสี่ยงจาก CDN ภายนอก
  2. ทุก script ภายในต้องมี cryptographic nonce กำกับ
  3. การอ้างอิงไฟล์รูปภาพหรือ css ในเครื่อง ต้องแปลงผ่าน webview.asWebviewUri(...)
